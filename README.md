# LinkBag

本机自托管的网页收藏备份室。把想留住的链接收进来，定期保存一份**可直接打开、外观与当时一致**的完整网页快照；再通过 Chrome 扩展从任何页面右键存入。

前端是 React 单页应用，后端是 Bun + Hono + SQLite。抓取由 SingleFile 在真实的 Chrome/Edge 中完成，快照是单个自包含的 HTML 文件，不依赖原站。

## 功能

- **高保真快照**：使用 SingleFile 保存 HTML、样式、字体和图片，生成一个自包含 HTML 文件，断网也能打开。微信公众号文章的视频会作为同一份备份的伴随 MP4 文件保存，并在归档页里换成可直接播放的本地播放器。
- **定时备份**：每个收藏可单独设置间隔，也可以用全局默认间隔；也可以随时手动备份。
- **低资源占用**：同一时间只抓取一个页面，只保留一个浏览器进程；浏览器按需启动，空闲后自动退出；普通网页的视频等大资源默认跳过，微信公众号视频按需串行下载。
- **内容去重**：快照按 SHA-256 比对，内容没变时用硬链接复用同一份文件，不重复占盘。
- **保留策略**：每个收藏只保留最近 N 份成功快照；失败记录另有上限。
- **本地控制台**：收藏列表、搜索、详情预览、备份历史、活动记录和设置。
- **Chrome 扩展**：右键存入页面或链接；点击图标查看收藏和每次快照，展开即可逐份打开。
- **插件扩展**：快照完成后可以运行插件，保存额外文件或改写归档 HTML。内置「微信公众号封面图」插件，会把文章封面和分享卡片图一起存进备份。

## 快速开始

要求：

- [mise](https://mise.jdx.dev/)
- 本机安装 Google Chrome、Chromium 或 Microsoft Edge

```bash
mise install       # 安装固定版本的 Bun
mise run setup     # 安装依赖
mise run start     # 构建前端并启动服务
```

打开 <http://127.0.0.1:8787>。

```bash
mise run dev       # 开发模式：API 8787 + Vite 5173
mise run build     # 只构建前端
mise run test      # 单元测试
```

开发模式下访问 <http://localhost:5173>，API 请求会代理到 8787。修改前端后刷新即可；修改后端代码时 API 进程会自动重启。

## 安装 Chrome 扩展

1. 打开 `chrome://extensions`。
2. 打开右上角「开发者模式」。
3. 点「加载已解压的扩展程序」，选择本仓库的 `extension/` 目录。
4. 建议把 LinkBag 固定到工具栏。

扩展默认连接 `http://127.0.0.1:8787`。如果改了端口或部署到了远程服务器，在扩展的「设置」里修改地址并保存；远程地址保存时会请求该地址的访问权限。

用法：

- 在网页空白处右键 →「存入 LinkBag」：收藏当前页面。
- 在任意链接上右键 →「存入 LinkBag」：收藏这个链接。
- 点击工具栏图标：查看收藏列表；点右侧箭头展开每一份快照；点标题打开最新快照；在展开区可以「现在备份」。

## 使用

- 左侧列表顶部可以搜索标题、域名或网址；`/` 聚焦搜索，`n` 打开新增表单。
- 新增收藏后会立刻排队抓取第一份快照。
- 详情页可以预览快照、修改这个收藏的备份间隔、暂停自动备份、立即备份或删除。
- 「活动」页显示正在备份、排队、即将到期和最近完成的任务。
- 「设置」页可以控制全局自动备份、默认间隔、保留数量，以及浏览器空闲多久后释放。

自动备份的判定每 8 秒检查一次。失败的任务会在约 15 分钟后重试；连续失败的收藏不会阻塞其他收藏。

## 快照与存储

数据默认在 `./data/`：

```text
data/
├── linkbag.db          # SQLite（WAL 模式）
├── archives/           # 每份快照一个 HTML 文件，伴随目录放视频和插件附件
├── plugins/            # 用户安装的插件
└── tmp/                # 抓取过程中的临时文件
```

快照通过独立的归档服务提供：

- 控制台/API：<http://127.0.0.1:8787>
- 归档站点：<http://127.0.0.1:8788/a/:id>

两个端口分开是刻意的：归档页面可能包含原站脚本，放在独立源上可以避免它读取控制台 API 或本地数据。归档响应带 `noindex`、`no-referrer`，页面在控制台里用沙箱 iframe 预览，下载时使用附件响应。

## 插件

插件在快照完成后运行。内置插件随代码放在 `plugins/`；用户插件放在数据目录的 `plugins/`（默认 `./data/plugins/`），在「设置 → 插件」里重新扫描并启用。插件的附件保存在 `archives/<id>/plugins/<pluginId>/`，和这份快照同生命周期，详情页的「插件保存的文件」里可以直接查看和下载。

- 内置的 `wechat-cover` 会保存微信公众号文章的主封面、1:1 / 16:9 分享图和正文首图，原图统一请求 `/0` 档位。
- 用户插件默认停用，需要手动开启；启用状态存在 SQLite 里。
- 插件和主进程同权限运行，**只安装你信任的代码**。

插件结构、manifest、`afterCapture` 钩子和 `ctx.saveAsset` API 见 [docs/plugins.md](docs/plugins.md)。

## 配置

环境变量（都有默认值，通常不需要改）：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `LINKBAG_HOST` | `127.0.0.1` | 控制台/API 监听地址 |
| `LINKBAG_PORT` | `8787` | 控制台/API 端口 |
| `LINKBAG_ARCHIVE_HOST` | `127.0.0.1` | 归档服务监听地址 |
| `LINKBAG_ARCHIVE_PORT` | `8788` | 归档服务端口 |
| `LINKBAG_PUBLIC_HOST` | 与监听地址一致 | 生成归档 URL 时使用的主机名 |
| `LINKBAG_ARCHIVE_ORIGIN` | `http://<publicHost>:8788` | 完整的归档源地址（反向代理时使用） |
| `LINKBAG_DATA_DIR` | `./data` | 数据库、快照和临时目录的位置 |
| `LINKBAG_CHROME_PATH` | 自动查找 | Chrome/Edge 可执行文件路径 |
| `LINKBAG_ALLOWED_ORIGINS` | 空 | 额外允许调用 API 的来源，逗号分隔 |
| `LINKBAG_CAPTURE_TIMEOUT_MS` | `150000` | 单次抓取的总超时 |

在 Windows PowerShell 中临时指定，例如：

```powershell
$env:LINKBAG_DATA_DIR = "D:\LinkBagData"
mise run start
```

## 资源占用

- 抓取串行执行，不会同时开多个浏览器页面。
- 浏览器在第一次备份时启动；没有任务时按设置的空闲时间退出，下一次备份再启动。
- SingleFile 默认跳过视频、压缩 HTML、移除隐藏元素；网络空闲后等待 500ms 再抓取，减少无谓等待。
- 微信公众号文章会额外读取页面里的视频直链并串行下载 MP4；默认最多 20 个、单个 200 MB、总计 500 MB，避免异常页面拖垮资源。视频和 HTML 同属一份备份，删除备份时会一起清理。
- 相同内容的快照通过硬链接去重，但每份备份仍保留自己的历史记录；内容没变时视频文件也会复用上一份，不重复占盘。

一次普通页面的抓取通常在几秒内完成；资源开销主要来自 Chrome 本身。

## 安全说明

LinkBag 是**本机个人工具**，默认只监听 `127.0.0.1`，请不要直接暴露到公网。

- 写操作要求 `X-LinkBag: 1` 请求头，降低跨站表单伪造的风险。
- CORS 只允许控制台自身、Vite 开发服务器、浏览器扩展来源，以及 `LINKBAG_ALLOWED_ORIGINS` 中显式列出的来源。
- 归档服务运行在独立端口，不参与 API 的 CORS 白名单。
- 归档页面被当作不可信内容：独立源 + iframe 沙箱 + 严格响应头。
- 插件与主进程同权限运行（可读写文件、访问网络），只安装你审阅过的插件；用户插件默认停用。

如果你确实要通过反向代理远程访问，请自行增加身份认证，并同时配置 `LINKBAG_PUBLIC_HOST`、`LINKBAG_ARCHIVE_ORIGIN` 和 `LINKBAG_ALLOWED_ORIGINS`。

## 项目结构

```text
server/
  index.ts        # 启动 API、归档服务和静态界面
  api.ts          # Hono 路由与 CORS
  db.ts           # SQLite 持久化、调度字段、保留策略
  queue.ts        # 串行备份队列、重试、去重
  plugins.ts      # 插件发现、钩子执行、附件写入
  engine.ts       # 抓取 worker 生命周期与空闲释放
  worker.ts       # 在 Chrome 中调用 SingleFile
  config.ts       # 环境变量、路径、浏览器查找
plugins/          # 内置插件（随镜像发布）
  wechat-cover/   # 微信公众号封面图
web/              # React 控制台
extension/        # Chrome MV3 扩展
docs/             # 插件文档与封面图提取规格
shared/types.ts   # 前后端共享类型
```

## 已知限制

- 快照是抓取那一刻的静态副本。需要登录、实时交互或依赖服务端状态的内容，之后不会自动更新。
- 部分站点会检测自动化浏览器，抓取可能失败；失败原因会显示在备份历史里。
- 目标站点返回人机验证或风控页面时，本次备份会被标记为失败，不会当成正常快照保存。
- 扩展支持本机和远程地址，但远程服务没有登录认证；请只连接可信网络中的 LinkBag，不要使用来历不明的地址。
- 归档页面里的原站脚本运行在独立源中；请不要在其中输入敏感信息。
- 微信公众号视频依赖文章里带时效的签名直链，只有在抓取成功时才能保存；下载失败的位置会显示“视频未能备份”。视频是归档 HTML 的伴随文件，通过 LinkBag 的归档地址打开时可直接播放，单独下载 HTML 文件则不包含视频。
- 插件保存的封面图等附件同样是 HTML 的伴随文件，通过 LinkBag 的归档地址访问；单独下载 HTML 文件不会包含它们。
- 插件在服务进程内运行，没有独立沙箱，超时或报错只会跳过该插件，不会让整次备份失败。
